# タスク: PR 自動レビューの導入と PoC

## 概要

`docs/pr-review-automation.md`（版 2.0）に基づき、GitHub Actions 上で Claude Code の公式 `code-review` プラグインを実行する PR 自動レビュー基盤を導入する。

現状、`main` は Ruleset で保護され PR 経由でしかマージできないが、Required approvals が 0 のため実効的なレビュー工程が存在せず、PR #8〜#11 はレビューなしでマージされている。この状態を解消する。

本仕様には未検証の前提が複数あるため、導入後に PoC を実施し、その結果で仕様を確定または撤退する。

## 期待される結果

- PR を作成すると Claude が自動でレビューし、総評とインラインコメントを日本語で投稿する
- `@claude` メンションで再レビューや質問ができる
- レビュー品質・利用枠の消費・実行時間が実測され、継続可否を根拠をもって判断できる
- 追加の金銭コストが発生しない（OAuth トークン方式＋Public リポジトリ）

## 対象範囲

- `.github/workflows/claude-review.yml` の新規作成
- Claude GitHub App のインストールと Secret `CLAUDE_CODE_OAUTH_TOKEN` の登録
- `docs/branching-rules.md` と `.github/pull_request_template.md` の改訂
- `CLAUDE.md` / `docs/pr-review-automation.md` の PR 化とマージ
- PoC の実施と評価、仕様の確定または撤退

## 対象外

- 既存 `.github/workflows/ci.yml` の変更
- Ruleset の変更（必須ステータスチェックへの追加を含む）
- `REVIEW.md` の作成（マネージド Code Review 専用の仕組みであり本構成では読まれない）
- アプリケーションコード・テストコードの変更（フェーズ7の検証用 PR を除く）
- `CLAUDE.md` への「仕様上の不変条件」節の追加（LINE Webhook 実装＝`plan.md` 7章 着手時に別タスクで実施）

## 制約

- 既存設計とプロジェクト規約（`docs/branching-rules.md`）を優先する
- `main` への直接 push は禁止。すべてトピックブランチ → PR → CI green → squash マージ
- コミット・push・PR 作成・マージは、依頼された場合のみ実行する
- 本リポジトリは **Public**。秘密情報を差分に混入させない
- 検証用 PR（フェーズ7）は既知の脆弱パターンを含むため**絶対にマージしない**

### 仮定

- 同一リポジトリ内のトピックブランチからの PR では、PR ブランチに含まれるワークフローファイルがその PR 自体に対して実行される（GitHub の標準挙動）。これによりフェーズ5でワークフロー導入 PR 自身を検証できる
  - 誤っていた場合: マージ後の次の PR で検証することになり、フェーズ5の一部がフェーズ6へずれる
- OAuth トークンでの認証は API キーと同様に動作する
  - 誤っていた場合: `ANTHROPIC_API_KEY` への切り替えを検討する（従量課金が発生するため要判断）

## ロールバック方針

- **ワークフロー**: `.github/workflows/claude-review.yml` を削除して push する。以後レビューは走らない
- **手書き方式への差し戻し**: `git show 7918fcf:docs/pr-review-automation.md` から 6.6 節を復元する
- **ドキュメント**: `docs/branching-rules.md` / `.github/pull_request_template.md` の変更を revert する
- **Secret**: Settings → Secrets and variables → Actions から `CLAUDE_CODE_OAUTH_TOKEN` を削除する
- **GitHub App**: Settings → GitHub Apps → Claude → Configure からリポジトリのアクセスを外す、またはアンインストールする
- **DB**: DB 変更なし

不可逆な変更は含まれない。ワークフローファイルの削除だけでレビューは即座に停止する。

## 結果・発見事項

- 2026-08-03: 公式 `code-review` プラグインのコマンド定義で、`--comment` 未指定時は GitHub へ一切投稿しない旨が明記されている（L63）一方、公式ドキュメントの GitHub Actions 例では `--comment` が省略されている。公式例をそのまま使うとレビューは完走するが何も投稿されず、ジョブは成功扱いで終わる。
- 2026-08-03: プラグインは「既に Claude がコメント済みの PR」をスキップする。このため `on: pull_request` に `synchronize` を含めると2回目以降が無言でスキップされる。`track_progress` の進捗コメントも同じ判定に引っかかる恐れがあるため無効化した。
- 2026-08-03: プラグインの除外リストに `lack of test coverage` が明記されており、テストの欠落は既定では指摘されない。`CLAUDE.md` に明示的な規約を書くことで初めて検出対象になる。
- 2026-08-03: `CLAUDE.md` 草案に技術スタックの誤記があった（`solid_queue` 等を採用と記載）。実際は `rails new` の既定生成物で未設定・未使用であり、仕様書 2.1 では Stage 2 から Sidekiq ＋ Redis を採用、Solid Queue は不採用。誤った規約はレビューの誤検知を誘発するため修正済み。
- 2026-08-03: **詳細仕様書のリポジトリ内取り込みを一度実施したが撤回した。** プラグインのコマンド定義を全件精査した結果、参照ファイルとして言及されるのは `CLAUDE.md` のみで（L24〜26 でルートおよび変更ファイルと同階層の `CLAUDE.md` を収集）、他のドキュメントは1箇所も登場しない。バグ検出エージェントには「差分そのものに集中し、追加の文脈を読むな」と明示指示がある（L36）。したがって**仕様書をリポジトリに置いてもレビュー内容は変わらず**、Public リポジトリへの公開という代償だけが残る。仕様準拠をレビューさせたい場合は、仕様書を置くのではなく**不変条件を規則の形に翻訳して `CLAUDE.md` に書く**必要がある。この作業は LINE Webhook 実装（`plan.md` 7章）着手時に行う。
- 2026-08-04: **Claude GitHub App のトークンは、ワークフローの `permissions:` ブロックでは絞られない。** `permissions:` が制御するのは自動生成の `GITHUB_TOKEN` のみで、App が発行するトークンは App のインストール権限をそのまま持つ（公式 `docs/security.md`）。実際の要求権限は公式ドキュメントの記載（Contents / Issues / Pull requests）より広く、**repository hooks と workflows への write を含む**。実効的な防御はツール制限であり、`auto-review` はプラグインの `allowed-tools`（`gh api` を含まない）、`mention` はワークフロー側の `--allowedTools` で塞ぐ。権限そのものを絞りたい場合は自作 GitHub App を使う。
- 2026-08-03: リポジトリを Private 化する案は採らない。無料の個人アカウントでは Private リポジトリで Ruleset も branch protection も使えず、`main` の直 push 禁止（`docs/branching-rules.md` の根幹）が失われる。維持するには GitHub Pro が必要で、Actions の実行時間も従量制になる。

- 2026-08-04: **ワークフロー変更を含む PR では自動レビューが走らない。** action は実行前にワークフローファイルがデフォルトブランチ上の内容と一致するかを検証し、不一致ならスキップする（PR でワークフローを書き換えて Secret を持ち出す攻撃への対策）。**ジョブは `success` で終わる**ため、ログを見ないと「レビューが走って指摘ゼロ」と誤認する。所要10秒程度が見分ける目安。今後 `claude-review.yml` を変更する PR にもレビューは付かない。

- 2026-08-04: **`--comment` は必要。** ローカル実行（`claude -p "/code-review:code-review <owner/repo>/pull/14 --comment"`）でレビューが完走し PR #14 に投稿された。公式ドキュメントの Actions 例が `--comment` を省略しているのは記載漏れと判断してよい。あわせて、**指摘ゼロ時の総評は日本語化できない**（プラグイン定義 L93〜99 の固定英文）。
- 2026-08-04: **Actions 経路のみ失敗する。** 認証（トークン再発行で不変）でもコマンド未解決（未解決時は `is_error:false` / `num_turns:0` / `duration_ms:8` で「Unknown command」を返すことを実測）でもない。初期化から結果まで 29ms で API 往復が無く、プロセス内で失敗している。エラー本文が伏せられており未特定。
- 2026-08-04: **ローカル実行という代替経路が使える。** マージ前に手動で実行すれば目的（レビューなしでマージしない）は満たせる。Actions 化は自動性のためであり必須ではない。撤退時の選択肢として記録する。
